A decision audit, not a second copy of the data

employee_reporting_audit joins an employee's raw fields to their inferred features, accepted manager, leading candidate, scores, thresholds and run hashes. Its decision_reason distinguishes low confidence, close candidates, missing candidates, pending inference and accepted links. The generated answer key is excluded.

SELECT full_name, inferred_manager, leading_candidate,
       confidence, margin, decision_reason
FROM employee_reporting_audit
WHERE company_id = 'cmp_0004';

What the database checks before serving

The published run must initially contain one model output per source employee. Afterward, a newly inserted employee appears immediately as pending_inference; live headcount and coverage views update before the model is rerun. Keys, accepted lines, decision counts and company coverage must reconcile. Self-management, cross-company links, cycles and invalid scores fail validation. A failed import leaves the previous snapshot intact.

This demo keeps one checked dataset snapshot. The hashes identify its inputs and model; historical employee versions and comparisons between stored runs would be the next extension.
