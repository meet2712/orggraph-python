      A short explanation

      From job titles to reporting lines

      The aim is to find managers when the evidence is useful and leave the rest open for review. A title alone will not always tell us who someone reports to.

      How it works

      1. Generate companies with a known hierarchy

        The Python generator creates {{ dataset.companies|count }} companies and {{ dataset.employees|count }} people across {{ dataset.industries }} industries, with {{ dataset.minimumCompanySize }}–{{ dataset.maximumCompanySize }} people per company. It adds abbreviations, typos, inconsistent casing, and missing fields. Clean reporting lines are saved separately to check predictions.

      2. Find plausible managers and score the matches

        Titles are cleaned up and used to infer function and seniority. Candidate managers come from the same company and must be more senior. A logistic regression model scores each pair using department, team, location, and the gap in seniority. Validation examples calibrate the scores.

      3. Keep a reporting line only when it clears both checks

        The leading candidate needs at least {{ model.threshold.probability|percent }} confidence and a {{ model.threshold.margin|points }} percentage point lead over the next candidate. Otherwise the manager stays unresolved. Each person has at most one inferred manager. Requiring a more senior manager prevents circular reporting chains.

      4. Test on companies the model has not seen

        The split uses whole companies: {{ split.trainCompanies }} for training, {{ split.validationCompanies }} for calibration and threshold selection, and {{ split.testCompanies }} for the final test. People from one company never appear in different splits. Predictions are compared with the generated direct manager.

      Why some people have no manager

      Two managers can have the same title, and missing team information can make them indistinguishable. Picking one would make the chart look more complete without making it more reliable. Those cases stay visible under “Needs review,” along with the leading candidate and its score.

      The chart uses inferred reporting lines. The generated answer is available separately in each person’s details, so you can inspect good matches and mistakes.

      What this version can tell us

      It shows how the approach handles messy generated records. It does not establish accuracy on real companies, where titles, reporting customs, and data quality will differ. The current model also misses many reporting lines in the generated data. Precision and coverage are shown together to make that tradeoff visible.

      Built in Python

      Python generates the dataset, trains the inference model, and renders the app with Flask and Jinja. The hosted version uses HTML pages exported by that same app. A small browser script handles search, filters, and opening a person’s details.

      Try it yourself

      The dataset package includes input records, generated answers, and the generator. The source package includes the Python app, inference pipeline, and instructions to run the checks.
